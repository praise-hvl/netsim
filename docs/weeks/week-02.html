The machine and its bus

Today you design the first part of your computer: the bus that connects everything, and the memory that stores bytes.

No code today. The goal for today's class is to create a design note and sketch of what the board will look like. Next week, we'll work on the rendering of the memory cells as the requests pass through the bus.

The machine you're designing a piece of. Today: the bus and memory.

Goals

  • Hardware idea: a computer is a few parts with different jobs (the CPU runs instructions, memory stores bytes, devices connect to the world). They share a bus and move in step with a clock. A memory access is a request and a reply across the bus. Memory is byte-addressableEvery byte has its own address: 0x010 and 0x011 are two different bytes. A read asks for one byte or several in a row.: 1 KB here, addresses 0x0000x means the number is written in hexadecimal (base 16). 0x010 is 16 and 0x3FF is 1023, so 0x000–0x3FF are the 1,024 bytes of 1 KB. to 0x3FF, and an address outside it is a faultA reply that says a request failed and why, for example OUT_OF_RANGE for an address memory doesn't have. It replaces the normal reply, so the asker always hears back., not a silent zero.
  • OS idea: the clock tickOne step of the shared clock. Every part does its work for the tick and tells the bus it's done; only then does the next tick start. is the system's heartbeat, and the bus is a shared resource that many parts want at the same time.
  • Design idea: before you build, decide the parts, what they say to each other, and what it looks like. That's the design note, and it's what you will use when building with your coding assistant next week.

Memory is 1 KB. Everything outside 0x000–0x3FF is a fault.

Take-home

Due before next session.

  1. Finish your design note in docs/notes/week-02.md, all nine sections. In particular:

    • Section 4, states and rules: memory's rule for a read or write that is partly outside 0x000–0x3FF. (Does a write that starts inside and ends outside change anything? Decide, and say why.)
