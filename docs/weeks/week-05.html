Week 5 · Design + build

A CPU that runs programs

Today is one class made of two weeks: week 4's design, then the build. You design the CPU core quickly, then you start talking to the agent in the app and build it. You guide the design, Codex may write the code, and you have to be able to explain every line it keeps. By the end of the take-home, the count-down and blink programs run on your board, with each core's fetch, decode and execute lighting up as it happens.

Week 4's page stays in the app as reference, but you don't need to have done it: everything from week 4 that matters is on this page.

The class tasks, in order. You design first, then the agent writes while you guide it.

Goals

  • Hardware idea: the fetch–decode–execute cycle. A program counter (PC) says where the next instruction is; registers hold the values being worked on; flags remember facts about the last result (was it zero? did it overflow?). Instructions are 4 bytes with an agreed encoding. Memory is slow: a LOAD takes a tick more than an ADD.
  • Design idea: a state machine is easiest to design as a table (from, event, to, what it does).
  • Software idea: a finite state machine written as a pure function: stepCore(core, reply) returns the new core and the effects it wants (a memory read or write); a thin shell turns effects into bus messages and latches replies until the next tick.
  • Working with an agent: you say your approach first, you read every change, and the tests decide when a task is done.

What "pure" buys you

const { core, effects } = stepCore(ready(0x010), null);
expect(core.phase).toBe("WAIT_FETCH");
expect(effects).toEqual([{ kind: "read", address: 0x010, length: 4 }]);

No socket, no timers, no waiting. Every row of the transition table is a three-line test. The CPU shell is what turns that read effect into a real mem.read on your bus.

Acceptance criteria

  • npx vitest run tests/week-04 tests/week-05 passes, and so does every earlier week (npx vitest run).
  • Every section of your note is filled in, with the storyboard there. Section 4 covers bytes not arrived yet, an invalid instruction, and a fault reply. Section 3 has your three hand-encoded instructions.
  • Every row of the CPU core's transition table has a test that passes.
  • The count-down program ends HALTED with R0 = 0, the zero flag set, and memory 0x3F20x means the number is written in hexadecimal (base 16). 0x010 is 16 and 0x3FF is 1023, so 0x000–0x3FF are the 1,024 bytes of 1 KB. holding 0.
  • core/ still imports nothing from components/, bus/ or app/.
  • With npm run dev:all, Load demo and Start, count-down and blink run on two cores, animated on /board: each core's step lights up, its fetches travel the bus, the LED blinks.
  • One commit per task (week 5: …, and week 4: decode, week 4: encode), and work is pushed.
